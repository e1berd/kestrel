# Kestrel — правила проекта

Kestrel (code name **volley**) — бесплатный open-source API-клиент на GPUI, альтернатива Postman и Bruno. Коллекции — обычные файлы в git, в формате OpenCollection YAML, который пишет Bruno 3.

Эти правила обязательны для всех разработчиков и AI-агентов и имеют приоритет над стилем сгенерированного кода. Общая основа — [e1berd/dotconfig](https://github.com/e1berd/dotconfig), здесь она переложена на Rust.

Стек: Rust 2024 (toolchain `stable`) · GPUI (`gpui-pre`) + `gpui-component` · tokio + reqwest (rustls) · QuickJS (`rquickjs`) для скриптов · `serde_yaml_ng`.

---

## 0. Устройство репозитория

| Крейт | Что в нём |
|---|---|
| `crates/volley-core` | Формат файлов, коллекция, окружения, переменные, отправка запросов, OAuth2, JS-скрипты, `report_error` |
| `crates/volley-openapi` | OpenAPI 3 → коллекция: импорт и повторный синк без потери правок |
| `crates/volley-cli` | `kestrel-cli`: запуск коллекций в терминале и CI, импорт и синк |
| `crates/volley-app` | Приложение `kestrel` на GPUI |

В `volley-app`:
- `appearance/` — дизайн-система: палитры, разворачивание в тему gpui-component, масштаб (`dp()`), шрифты, режим для слабовидящих;
- `workspace/` — окно: несколько открытых проектов, лента проектов, заголовок, экран приветствия;
- `project_view/` — один проект: дерево, вкладки, действия над деревом, синк OpenAPI;
- `request_tab/` — вкладка запроса: сборка файла из полей, редакторы, отправка, ответ;
- `settings/` — настройки.

## 1. Совместимость с Bruno — главный контракт

- Kestrel читает и пишет коллекции Bruno 3 (OpenCollection YAML) **байт в байт**: открыть и сохранить файл без правок — нулевой `git diff`.
- Сохранение идёт через `Document::save`: он сливает новые данные со старыми (`yaml::merge`), сохраняя порядок ключей и пустые строки между секциями. Писать YAML в обход `Document` нельзя.
- Незнакомые ключи хранятся в `extra` каждой структуры `format.rs` и никогда не теряются.
- Сгенерированное из OpenAPI должно совпадать с тем, что генерирует Bruno: повторный синк из того же spec — **0 изменённых файлов**.
- Проверка на настоящей коллекции:
  ```bash
  KESTREL_COMPAT_DIR=/путь/к/коллекции cargo test -p volley-core --test compat
  ```

## 2. Без поясняющих комментариев

Код самодокументируемый: имя функции, типа, переменной и структура выражают намерение.

- Запрещены комментарии, пересказывающие код: `//`, `///`, `//!` с описанием «что делает».
- Doc-комментарий допустим только там, где он несёт информацию, которую нельзя выразить типом.
- Непонятный без комментария фрагмент — сигнал переименовать или вынести в функцию/модуль.
- Исключение — внешние ограничения, которые нельзя вывести из кода (обход бага в чужом крейте, требование системы). Пример: установка TLS-провайдера в `main.rs`.

### 2.1. Имя вместо комментария

- **Блок разметки → функция `render_…`** с говорящим именем (как `render_tab_strip`, `render_env_picker`), а не комментарий над куском `div()`.
- **Шаг функции → функция**, названная тем, что сказал бы комментарий:
  ```rust
  // Было
  fn open_request(&mut self, path: &Path, cx: &mut Context<Self>) {
      // раскрыть папки до запроса
      let folders = …;
      self.expanded.extend(folders);
      …
  }

  // Стало
  fn open_request(&mut self, path: &Path, cx: &mut Context<Self>) {
      self.expand_ancestors(path, cx);
      …
  }
  ```
- **Разделение по смыслу**: растущая вьюха делится на модули с `impl Type` по ответственности (`request_tab/{build,sending,sections,response,url_bar}.rs`), а не просто на файлы поменьше.

## 3. Размер файлов

- Ориентир — до 350 строк, жёсткий потолок — 400 (Rust, JS-прелюдия скриптов, JSON-темы не в счёт).
- Переросший файл сразу делится: логика — в отдельные модули и функции, разметка — в `render_…` в своих файлах.

---

## 4. Версии и зависимости

- Только актуальные стабильные версии. Перед добавлением крейта проверить последнюю версию на crates.io (`cargo search`, `cargo info`), а не брать из памяти.
- Никаких крейтов, функциональность которых требует платной подписки или проприетарной лицензии.
- Deprecation-предупреждения чинятся сразу.
- `gpui-pre` и `gpui-component` обновляются вместе: у gpui-component строгая зависимость `=0.3.x` на gpui-pre.

---

## 5. Ошибки: никаких немых

Каждая перехваченная ошибка попадает в единую точку `volley_core::report::report_error` (stderr + `~/.local/state/kestrel/errors.log`).

- Запрещено: `let _ = result;`, `.ok();` без обработки `None`, `unwrap_or_default()` там, где ошибка что-то значит.
- `result.report_err("что делали")` — когда нужно сообщить и продолжить (`ReportExt`).
- `weak.update(cx, …).report_unless_gone("что делали")` — обновление сущности GPUI из замыкания: ошибки «сущность уже закрыта» отсекаются централизованно внутри, остальные отправляются.
- Ошибка, которую видит человек, показывается уведомлением (`window.push_notification`) или в интерфейсе; пробрасываемую дальше через `?` отдельно сообщать не нужно.

## 6. Дизайн-система

- **Цвета только из темы**: `cx.theme()` (поля gpui-component) или `appearance::palette(cx)` (методы, статусы). Никаких hex-литералов во вьюхах.
- **Цветовая схема** — JSON с двумя палитрами (`light`, `dark`) из ~20 семантических токенов: `background`, `surface`, `raised`, `border`, `hover`, `text`, `muted`, `accent`, `accent_text`, `selection`, `success`, `warning`, `danger`, `info`, `methods.{get,post,put,patch,delete,other}`.
  - Встроенные: `crates/volley-app/assets/themes/*.json` (+ строка в `palette::BUILT_IN`).
  - Пользовательские: `~/.config/kestrel/themes/*.json` (кнопка «Make my own» в настройках копирует текущую).
  - Во все ~100 полей gpui-component токены разворачивает `appearance/expand.rs`. Новый токен добавляется туда, а не точечно во вьюху.
- **Размеры**: структурные (ширины панелей, отступы, иконки) — через `dp(…)`, они следуют масштабу интерфейса. Высота строк с текстом — в `rems(…)` или `text_*`, тогда она следует размеру текста. Голый `px(…)` в разметке не используется.
- **Шрифты**: Inter (интерфейс) и JetBrains Mono (код) встроены статическими начертаниями: variable-шрифт GPUI рисует всеми весами как Regular.
- Режим для слабовидящих: +25% к масштабу и высокий контраст (`expand::raise_contrast`). Новые элементы должны оставаться читаемыми в нём.

## 7. GPUI

- Сеть и скрипты — на `volley_core::runtime()` (tokio), результат ждётся в `cx.spawn_in`. Блокирующий ввод-вывод — в `cx.background_spawn`. UI-поток не блокируется никогда.
- В замыканиях меню и диалогов — `WeakEntity` (`cx.entity().downgrade()`), не сильные ссылки.
- Шорткаты задаются макросом `primary!("s")` (Cmd на macOS, Ctrl на остальных): `KeyBinding::new` в gpui 0.3.10 не понимает `secondary-`.
- Состояние, которое переживает перезапуск, лежит в `Prefs` (`~/.config/kestrel/prefs.json`), никогда не в коллекции.

---

## 8. Файлы инфраструктуры и секреты

- `.env` коллекций, `docker-compose*.yml` и подобные файлы меняются только с разрешения пользователя или по его просьбе. `Cargo.toml` — можно.
- Секреты не попадают в коллекцию: для них `.env` рядом с `opencollection.yml` (он в `.gitignore`) и `{{process.env.NAME}}`.

---

## 9. Именование

Говорящие имена без сокращений: `palette`, `request`, `collection`, а не `p`, `req`, `col`. Исключение — устоявшиеся в предметной области `url`, `id`, `cx`, `jwt`, и имена из API Bruno (`bru`, `req`, `res`) в JS-скриптах.

## 10. Гейты качества

На `stable` нет rustfmt и clippy, поэтому они запускаются на 1.92 (там, где хватает этой версии):

```bash
cargo +1.92.0 fmt --all --check
cargo +1.92.0 clippy -p volley-core -p volley-openapi -p volley-cli --all-targets
cargo test --workspace
KESTREL_COMPAT_DIR=/путь/к/коллекции cargo test -p volley-core --test compat
```
